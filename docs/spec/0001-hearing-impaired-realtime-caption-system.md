# 规格：听障实时字幕气泡展示系统（MVP）

## Problem Statement

作为听障用户，我身处一个 3-5 人的现场对话中，无法听清别人在说什么。我需要一个桌面软件，实时把周围人说的话转成文字，并清晰区分"谁在说"——按说话人显示成不同颜色的气泡和头像，让我能跟上对话节奏。对话中的口语化文字最好能自动整理成通顺的书面语，方便阅读；对话结束后，我还希望能得到一份整理好的会议纪要。我要能按自己的阅读习惯自定义显示（文字大小、颜色、字体、滚动方式、头像），并且这个软件要同时能在 Mac 和 Windows 上使用。

## Solution

一套桌面应用：开启后从麦克风实时采集现场多人对话，本地流式语音识别（可选云端 ASR）边说边出字，按说话人自动分组成彩色气泡 + 随机头像，气泡流自动滚动。文字经 LLM 按可配置间隔（5s/10s）自动整理成通顺书面语，默认只显示整理版（原文一键切换查看，改动词高亮）。停止识别后可一键把整段内容分批交给 LLM 生成结构化会议纪要。所有设置集中在标签页中、每项带操作提示。软件托盘常驻、全局热键唤出。历史会话本地保存并可导出（Markdown/TXT/SRT）。

## User Stories

1. 作为听障用户，我希望软件能常驻在系统托盘并在需要时用全局热键唤出，以便随时开始捕捉身边的对话。
2. 作为听障用户，我希望一键开始识别后从麦克风实时采集现场声音，以便看到周围人正在说的话。
3. 作为听障用户，我希望识别是流式的（说话中途就出字，不等话说完），以便跟上实时对话节奏。
4. 作为听障用户，我希望默认用本地语音识别（离线、免费、隐私好），以便敏感对话不外传。
5. 作为听障用户，我希望能在设置中切换到云端 ASR 并配置 API，以便本地识别质量不够时用更强的云端识别。
6. 作为听障用户，我希望系统按说话人自动区分内容，以便知道是谁在说话。
7. 作为听障用户，我希望每位说话人自动编号（说话人 1/2/3），以便区分不同发言者。
8. 作为听障用户，我希望每位说话人的内容显示为不同颜色的气泡，以便视觉上一眼区分。
9. 作为听障用户，我希望每位说话人配一个随机头像，以便更容易记住谁是谁。
10. 作为听障用户，我希望头像性别能根据音色自动选择（男声/女声），以便头像与实际说话人更匹配。
11. 作为听障用户，我希望能在界面上手动重命名说话人（把"说话人 2"改成"张三"），以便识别真实身份。
12. 作为听障用户，我希望气泡流自动滚动到最新内容，以便不用手动操作就看到新对话。
13. 作为听障用户，我希望上翻回看时自动滚动暂停、回到底部后恢复，以便阅读不被突然打断。
14. 作为听障用户，我希望能在主窗口和"置顶大字模式"之间切换，以便对话中始终保持字幕可见。
15. 作为听障用户，我希望置顶大字模式下字体超大、始终置顶，以便远距离或低视力也能看清。
16. 作为听障用户，我希望界面深浅主题跟随系统并可手动覆盖，以便各种光线下都舒适。
17. 作为听障用户，我希望自定义文字大小、颜色、字体，以便按我的阅读习惯显示。
18. 作为听障用户，我希望自定义滚动方式，以便选择最适合我的阅读方式。
19. 作为听障用户，我希望能自定义随机头像（开关/换一批），以便获得更顺眼的显示。
20. 作为听障用户，我希望识别出的文字能被 LLM 自动整理（去口语化、纠错、补标点），以便阅读更通顺。
21. 作为听障用户，我希望整理间隔可配置（5s/10s），以便平衡实时性与整理质量。
22. 作为听障用户，我希望界面默认只显示整理版文字，以便阅读体验最佳。
23. 作为听障用户，我希望一键切换显示原文，以便核对识别是否准确。
24. 作为听障用户，我希望整理版中改动的词有高亮提示，以便知道哪些文字被修改过。
25. 作为听障用户，我希望整理失败时保留原文，以便内容不丢失。
26. 作为听障用户，我希望停止识别后一键生成结构化会议纪要（要点/行动项/待办），以便会后回顾。
27. 作为听障用户，我希望内容太多时系统自动分批交给 LLM 再汇总，以便长对话也能生成纪要。
28. 作为听障用户，我希望会话自动保存到本地，以便不丢失记录。
29. 作为听障用户，我希望能查看历史会话列表并重新打开，以便回顾以前的对话。
30. 作为听障用户，我希望会话能导出为 Markdown/TXT/SRT，以便分享或归档。
31. 作为听障用户，我希望所有设置集中在一个界面（标签页分组），以便快速找到并调整。
32. 作为听障用户，我希望每项设置都有操作提示，以便知道它有什么用、怎么配。
33. 作为听障用户，我希望 ASR 配置包含本地引擎与云端 API 配置，以便自由选择识别来源。
34. 作为听障用户，我希望 LLM 配置支持 OpenAI 兼容接口（Base URL + API Key + 模型名），以便使用 DeepSeek/豆包/OpenAI/本地 Ollama 等任意服务。
35. 作为听障用户，我希望会话结束后能按说话人区分查看整理文本，以便理清每个人的发言。
36. 作为听障用户，我希望识别和整理过程中界面有状态提示（识别中/整理中），以便知道系统在正常工作。
37. 作为听障用户，我希望说话人在长会话中保持颜色稳定不跳变，以便不会看混。
38. 作为陪同者（听力正常），我希望我能帮听障用户命名说话人，以便字幕更有意义。
39. 作为听障用户，我希望应用支持中文为主 + 中英混合识别，以便符合实际对话。
40. 作为听障用户，我希望应用在 Mac 和 Windows 上都能运行，以便在不同电脑上使用。
41. 作为听障用户，我希望对话出现重叠说话时系统保持稳定不崩溃，以便可靠使用。
42. 作为听障用户，我希望重启应用后设置与历史保留，以便不用每次重配。
43. 作为听障用户，我希望每条发言知道对应时间，以便回看时定位。
44. 作为听障用户，我希望能在识别中暂停/继续，以便处理中断（接电话、他人插话）。

## Implementation Decisions

### 模块结构与职责

- **engine 核心库**（Rust crate，无 Tauri 依赖）：承载全部业务逻辑——不可变片段管理、说话人切换检测、整理队列与单写入、会话与纪要编排。定义三个可注入端口：`AsrPort`（产出原文片段）、`EmbeddingPort`（产出说话人向量）、`LlmPort`（产出整理文本与摘要）。对外暴露统一的事件流。
- **Tauri 壳**（Rust，薄胶水）：音频采集（cpal 麦克风）、本地 sherpa-onnx 流式 ASR 绑定、云端 ASR 客户端、LLM HTTP 客户端（OpenAI 兼容，SSE 流式）、托盘/全局热键/单实例/窗口管理。负责把外部能力接入 engine 的三个端口，并经 Tauri Event 把 engine 事件流推给前端。
- **Web 前端**（React 或 Vue + CSS）：只渲染事件流——气泡、头像、主题、滚动、原文/整理版切换。刻意不承载业务逻辑，以保持单一测试缝。

### 技术决策（对齐 ADR）

- **ASR 抽象**：本地（sherpa-onnx 流式，默认）与云端（OpenAI 兼容或厂商 SDK）实现同一 `AsrPort`，设置中可切换（ADR-0002）。
- **说话人切换检测（SCD）**：VAD 切句 + speaker embedding 余弦匹配，超过阈值归入现有说话人，否则新建；不做全自动在线 diarization（ADR-0002）。头像性别按说话人音色特征选择。
- **整理管线**（ADR-0003）：不可变片段；防抖（2s 无追加）∪ 固定节奏（5s/10s）触发 freeze 最老的 active 片段；整理队列按 id 有序、单在途请求；单 writer 写入，editId 单调递增、只接受更大值；只整理 frozen 片段，interim 不送 LLM；失败重试退避 3 次后展示原文。
- **双轨展示**：原文与整理版并行存储；前端默认只显示整理版，一键切换显示原文；整理版对改动词做差异高亮（借鉴 CARTGPT 做法）。
- **纪要编排**：停止后把片段按时间窗分批（每批约 500 字 + 滚动上文，上限 2000 token）交给 `LlmPort`，再汇总为结构化纪要（要点/行动项/待办）。
- **LLM 配置**：OpenAI 兼容接口（Base URL + API Key + 模型名），整理与纪要复用同一管线；内置"整理人设"预设（参考本机 TypeFlux 的意图整理人设，已提取）。
- **设置模型**：标签页分组（常规/ASR/LLM 整理/显示/快捷键/历史/关于），每项带操作提示，持久化到本地配置。
- **会话持久化**：会话（原文与整理版片段、说话人、时间）本地保存；历史列表可重新打开；导出 Markdown/TXT/SRT。
- **置顶大字模式**：主窗口之外的显示形态，始终置顶 + 超大字体（用户故事 14/15）。

### 数据契约（来自设计共识，见 ADR-0003）

engine 事件的决策性形状：

```ts
type SegmentStatus = 'active' | 'frozen' | 'cleaned' | 'failed';
interface Segment {
  id: number;            // 全局单调递增，排序与去重键
  speakerId: number;     // 所属说话人
  raw: string;           // 不可变原文，只写一次
  status: SegmentStatus;
  cleaned?: string;      // 整理结果
  editId?: number;       // 写入时单调 id，渲染层只接受更大的
  ts: number;            // 最后追加时间（防抖基准）
  retries: number;
}

type EngineEvent =
  | { type: 'sessionStarted' } | { type: 'sessionStopped' }
  | { type: 'segmentAppended'; segment: Segment }
  | { type: 'speakerAssigned'; segmentId: number; speakerId: number; isNewSpeaker: boolean }
  | { type: 'segmentCleaned'; segmentId: number; cleaned: string; editId: number }
  | { type: 'cleanupFailed'; segmentId: number }
  | { type: 'minutesReady'; minutes: string };
```

## Testing Decisions

- **好测试的定义**：只测 engine 缝上的外部行为——喂入合成事件（模拟 ASR 的文本片段 + 预计算的 embedding + 模拟 LLM 返回），断言输出的事件流，不触及实现细节。测试中无真实音频、无网络、无 WebView。
- **被测模块**：engine 核心库（唯一测试缝），覆盖：
  - 片段 freeze/整理时序：防抖 + 固定节奏触发是否符合预期，interim 不送 LLM；
  - 并发正确性：editId 单调校验下不丢字、不乱序，旧结果不覆盖新结果；
  - SCD：embedding 余弦匹配 → 归入现有说话人 / 新建说话人；
  - 失败兜底：LLM 失败重试退避后展示原文，待整理池不无限累积；
  - 纪要编排：分批边界（500 字/2000 token）与汇总顺序。
- **先例**：绿色field 无既有测试；engine 采用 Rust 单元测试 + 注入 mock 端口。工程参考（来自调研报告）：cnblogs Whisper+GPT demo 的单 writer/队列防竞态设计、LiveTranslate 的 ASR→LLM→流式字幕管线、CARTGPT 的整理与高亮思路。
- **前端**：刻意薄渲染，其交互（滚动暂停、原文/整理版切换）的组件测试延后到 UI 层出现后再评估，不加入本缝。

## Out of Scope

- **打包/签名**（DMG/MSI 与代码签名）：延后，开发期用开发模式运行（用户已决定先跑通流程）。
- **在线会议/系统音频采集**（WASAPI loopback / BlackHole / ScreenCaptureKit）：MVP 只做面对面麦克风采集（Q1=A）。
- **气泡回放**（点击回听录音片段）。
- **全自动在线说话人分离（diarization）与自动认人**：仅做切换检测 + 手动命名。
- **超出中英双语的多语言识别**。
- **跨天说话人身份持久化**（说话人模板库）。
- **云端 diarization 作为默认**（讯飞/Azure 增强）。
- **移动端**。
