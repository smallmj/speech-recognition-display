# 实时语音识别展示系统——竞品与开源方案调研报告

> 调研时间：2026-08 · 方法：GitHub 官方 API（star 数为调研当日实时值）+ 各仓库 README 原文 + 官网/文档交叉验证。所有结论均落到具体项目与链接，star 数以本文为准。

## 0. 执行摘要（先看这里）

针对目标系统（**桌面双端 macOS+Windows · 实时流式多人语音转写 · 按说话人分色气泡 + 随机头像 · 文字滚动/自定义样式 · 本地/云端 ASR 可选 · 边识别边交给 LLM 整理 · 停止后生成会议纪要**），结论如下：

| 结论 | 说明 |
|---|---|
| **没有任何一个现成开源项目完全符合"彩色气泡 + 随机头像 + 实时多说话人"** | 最近的三个候选各有硬伤，详见第 4 节差距分析 |
| **ASR 引擎层完全不需要从零做** | faster-whisper / FunASR(Paraformer) / sherpa-onnx / Vosk / WhisperLiveKit 都是成熟可嵌入的流式内核 |
| **桌面壳与音频采集不需要从零做** | Tauri(Rust)+Web 是当下最优解（vibe、Meetily 均已验证），macOS ScreenCaptureKit / Windows WASAPI Loopback 是现成方案 |
| **真正的原创点/工作量集中在**：按说话人实时分组的彩色气泡流 + 随机头像 + 滚动/样式定制这一整套 UI 与状态管理，以及"边说边整理"的流式 LLM 管线（现有一律停止后才整理） |
| **唯一形态上最接近的商业参照是 Ava（闭源）** | Ava 正是"为听障人士设计 + 桌面端 + 按说话人彩色标签 + 头像"，但它闭源且是订阅制 |

> 一句话：**建议"拼装式开发"**——用开源 ASR 内核 + Tauri 壳 + 自研气泡 UI 管线，而不是从零写或套用某个现有仓库。

## 3. 架构启示（现有项目如何搭，可复用什么）

### 3.1 前端框架 / 桌面壳
- **主流最优解：Tauri（Rust 后端）+ Web 前端**（React/Next.js/Vue）。`vibe`、`Meetily` 都是这套：体积小、双端打包成熟、Web 生态做气泡/动画/主题最顺手。✔ 推荐走这条路
- 备选：Electron（SmartSub 等；生态熟但体积大）、Python + FastAPI + 浏览器 WebUI（jt-live-whisper 的 WebUI 模式，开发最快但体验次）、纯原生（LiveCaptions 用 C++/GTK，不推荐自研时选）
- 前端渲染"气泡流"：直接用 Web 技术（CSS 气泡 + 随机头像 emoji/素材 + 虚拟滚动）远比原生绘制省事

### 3.2 音频采集（多说话人会议场景的关键）
- macOS：**内置 ScreenCaptureKit**（无驱动，捕获系统输出）或 Audio Unit；系统音频可用时配合虚拟设备（BlackHole）。jt-live-whisper 用 ScreenCaptureKit，jiji262 用 BlackHole
- Windows：**WASAPI Loopback**（捕获系统输出，无需驱动）
- 双端都要支持"麦克风 + 系统输出"两路，Meetily 还做了智能 ducking（压低系统音量避免啸叫）

### 3.3 ASR SDK 绑定方式
- Python 系：faster-whisper / FunASR / WhisperLiveKit（PyPI 一键装，GPU/CUDA/Metal 自动）
- Rust 系（Tauri 后端直接嵌）：whisper-rs、`whisper.cpp` 绑定、Parakeet（Meetily 用的 4x 实时模型）
- C/C++ 嵌入式：sherpa-onnx（onnxruntime，12 语言绑定，可进 Qt/原生壳）
- Swift 系（macOS 原生）：MLX-whisper / argmax-oss-swift（Metal 加速）
- 建议：**Rust 后端里跑本地 ASR（whisper.cpp/Parakeet）+ 可选云 ASR（OpenAI/豆包/讯飞/阿里云）双引擎**，满足"本地/云端可选"

### 3.4 流式（边说边出字）的实现策略
- 不要对整句 Whisper：采用 **LocalAgreement / AlignAtt 提交策略**（ufal/whisper_streaming → WhisperLiveKit）或 **VAD 分段 + 增量重转写**（sliding window，faster-whisper 常见做法）
- 词级/字级时间戳驱动滚动：whisperX 的 word-timestamp 思路可借鉴到流式
- FunASR 的 Paraformer-zh-streaming 本身就是为 WebSocket 增量设计的，中文场景直接可用

### 3.5 说话人分离（多说话人着色的底层）
- 离线/准实时：pyannote / resemblyzer+spectralcluster / CAM++（FunASR），对一段音轨聚类出说话人 id
- 实时流式：`diart`、`ishine/StreamingSpeakerDiarization`（增量聚类）；WhisperLiveKit 的 Streaming Sortformer 是目前流式 diarization 的 SOTA 开源实现
- 现实约束：**流式 + 实时多人 + 稳定颜色**是当前开源最弱的一环，多数项目（Meetily、jt-live-whisper 的实时模式）在实时模式下要么不分离、要么分离质量打折，只有离线处理才可靠着色。这是本项目最大的技术风险点，见 §4

### 3.6 UI 方案（气泡 / 字幕 / 滚动）
- 现成做法分三派：**时间轴转写列表**（vibe、Meetily）、**字幕浮层**（LiveCaptions-Translator overlay、abb128/LiveCaptions）、**聊天气泡流**（jt-live-whisper WebUI，左/右气泡按语言分栏）
- 字体/字号/颜色/大小写/透明度/显示句数可调：abb128/LiveCaptions 与 LiveCaptions-Translator 都实现了，可直接抄配置交互
- 目标形态（气泡+头像+滚动）在 Web 端实现成本不高，但**没有人开源过现成的**

### 3.7 LLM 整理（去口语化 / 纠错 / 纪要）
- 本地：Ollama（Meetily、jt-live-whisper、wendao 都用，支持 OpenAI 兼容接口）
- 云端：OpenAI 兼容端点（Groq/Claude/OpenRouter/自定义）
- 现有做法都是**停止后一次性整理**（wendao 的"按需生成纪要"最优雅：转写完成即可用、不阻塞）；"边说边整理"尚无现成管线，需要自研（把增量转写文本流式喂给 LLM，或定时快照）

### 4.2 逐项结论

1. **最接近的"功能全链路"候选：`jt-live-whisper`**（本地流式+翻译+讲者辨识+LLM 纪要+WebUI，macOS/Win 双端音源采集）——但它**没有**：按说话人着色的实时气泡、随机头像、实时模式下的稳定说话人分离（颜色区分主要在离线处理）。

2. **最接近的"产品成熟度"候选：`Meetily`（29k★）**——Tauri 双端、实时转写、本地 Ollama 纪要，产品最完整——但**免费版没有说话人分离**（PRO 才规划），UI 是会议记录时间轴，无气泡无头像。

3. **最接近"气泡 UI"的候选：`jt-live-whisper` 的 WebUI**——聊天气泡布局有了，但气泡左右分栏是**按语言（源/译）**，不是按说话人，且无头像。

4. **最接近"听障人士彩色多说话人"的商业参照：`Ava`**（[官网](https://www.ava.me)、[SpeakerID 说明](https://help.ava.me/en/articles/9741631-speakerid-for-live-captioning-on-my-computer-beta)）——专为聋/听障设计、桌面+Web、**彩色说话人标签 + 头像**，形态最像，但**闭源订阅制**，无法复用代码，只能当产品对标。

5. **有没有完全符合的？没有。** 把"实时多说话人 + 彩色气泡 + 随机头像 + 滚动/样式定制 + 本地/云端可选 + 边说边整理 + 停止后纪要"全部集齐的开源项目，调研中不存在。

### 4.3 要不要从零做？—— 建议"拼装式"，而非全从零

**需要自研（核心竞争力，也是工作量主体）：**
- 按说话人实时分组的**气泡流状态管理 + 随机头像 + 滚动控制 + 主题定制**（Web 前端，无现成开源，但实现难度中等）
- **实时流式说话人分离的工程化**（颜色稳定不跳变 + 实时多人），可基于 diart/StreamingSortformer 调优
- **边说边整理的流式 LLM 管线**（增量文本 → 定时整理），无现成实现

**不要从零做（直接嵌入）：**
- ASR：FunASR（中文）/ faster-whisper（多语）或 sherpa-onnx（全离线）双引擎切换
- 桌面壳：Tauri(Rust)
- 音频采集：ScreenCaptureKit / WASAPI Loopback
- 说话人分离基础件：CAM++ / pyannote / resemblyzer
- 纪要：Ollama + 现有提示词方案（wendao/Meetily 可抄）
