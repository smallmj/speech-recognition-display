# 跨平台桌面应用框架选型调研报告

> **场景**：macOS + Windows 双端桌面应用
> **核心需求**：① 持续音频采集（麦克风 + 系统音频 loopback，用于在线会议字幕）；② 流畅动画 UI（滚动气泡、彩色主题、字体控制）；③ 系统托盘/常驻（后台挂机）
> **候选**：Tauri 2.x（Rust + Web）、Electron（Node + Web）、Flutter Desktop、Qt/C++（QML/Widgets）、.NET MAUI、原生双端各写一套、"轻量本地服务 + Web 前端"混合架构
> **调研方式**：基于官方文档与真实项目的一手信源（web_search + 直接抓取官方页面核实），日期 2025 年。

---

## 1. 音频采集

### 1.1 麦克风录音（各框架难度）

| 框架 | 路径 | 备注 |
|---|---|---|
| **Tauri 2.x** | ① Web 前端 `getUserMedia` + `MediaRecorder`（macOS WKWebView / Windows WebView2）② Rust 端 [cpal](https://crates.io/crates/cpal)（跨平台，底层 macOS CoreAudio / Windows WASAPI）③ 社区插件 [tauri-plugin-audio-recorder](https://github.com/brenogonzaga/tauri-plugin-audio-recorder)（桌面+移动） | **生产路径建议走 Rust cpal**：不依赖 WebView 的 getUserMedia 行为差异；macOS 需 `NSMicrophoneUsageDescription` + 系统权限授权 |
| **Electron** | Chromium 内建 `getUserMedia` + `MediaRecorder` | 最成熟，权限模型与浏览器一致 |
| **Flutter Desktop** | [`record`](https://pub.dev/packages/record) 插件 | 支持 macOS/Windows 麦克风录音，成熟 |
| **Qt/C++** | `QAudioSource`（Qt Multimedia，官方跨平台） | 官方成熟 API，见 [QAudioSource 文档](https://doc.qt.io/qt-6/qaudiosource.html) |
| **.NET MAUI** | Windows：NAudio/CSCore（WASAPI）；macOS：支持弱（MAUI 桌面音频基本空白，需自写原生） | 表现力弱，不推荐 |
| **原生双端** | macOS AVFoundation/CoreAudio + Windows WASAPI | 最强但工作量翻倍 |

### 1.2 系统音频 loopback（录"系统播放的声音"，会议字幕核心需求）

> 这是**本项目最关键、最容易踩坑**的一环，两个平台情况完全不同。

#### Windows —— 官方有标准 API：WASAPI loopback

- 微软官方文档：[Loopback Recording（Win32 Core Audio）](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)，用 `IAudioClient` 的 loopback 模式即可采集系统输出（含会议 App 声音）。
- 各框架落法：
  - **Tauri/Rust**：直接用 Rust 调 WASAPI —— `cpal` 不直接暴露 loopback，但 [`wasapi` crate](https://docs.rs/wasapi/) 或微软官方 [`windows` crate](https://crates.io/crates/windows) 可以。真实项目佐证：**[taurscribe](https://github.com/machowdh/taurscribe)** —— "A Tauri application that translates desktop audio and displays it using Whisper and PyAudio with WASAPI"，与你的场景一模一样，且已有源码可参考。
  - **Electron**：Chromium `desktopCapturer` + `getUserMedia`（录整个屏幕输出带系统音频）在 Windows 可用（见 [Electron 文档 desktopCapturer](https://www.electronjs.org/docs/latest/api/desktop-capturer) 与 [issue #25120](https://github.com/electron/electron/issues/25120)）；更精细的方式是 native addon 调 WASAPI，如 [electron-audio-loopback](https://github.com/alectrocute/electron-audio-loopback)。
  - **Flutter**：社区包 `flutter_f2f_sound`（实验性）、`desktop_audio_capture`（0.0.1 极早期）；[flutter-webrtc issue #1952](https://github.com/flutter-webrtc/flutter-webrtc/issues/1952) 明确反馈 **WebRTC 在桌面端无法采集系统音频**。基本要自写 platform channel 调原生。
  - **Qt/C++**：`QAudioSource` 不直接支持 loopback，需自己写 WASAPI loopback 平台代码（[CSDN 佐证](https://blog.csdn.net/ok6018234/article/details/132003416)）。
  - **.NET MAUI**：Windows 上 [NAudio](https://github.com/naudio/NAudio) 3.0 提供 `WasapiLoopbackCapture`，成熟；但 macOS 侧无对应。
  - **原生双端**：Windows 侧 WASAPI loopback 直接写，成熟。

#### macOS —— 没有"纯音频 loopback"的官方 API，两条路

macOS 的系统音频采集历史上只能靠**虚拟声卡**或较新的 **ScreenCaptureKit**（macOS 13+）：

- **方案 A：BlackHole 虚拟声卡**（推荐给"自己选播放设备"的场景）
  - 官方开源项目 [ExistentialAudio/BlackHole](https://github.com/ExistentialAudio/BlackHole)："modern macOS audio loopback driver that allows applications to pass audio to other applications with zero additional latency"。
  - 做法：配合「音频 MIDI 设置」创建多输出设备（扬声器 + BlackHole 聚合），应用把输出指向该设备，再从 BlackHole 采集。任何能读输入设备的框架（cpal / QAudioSource / Electron）都能从 BlackHole 读。
  - 缺点：**需要用户安装驱动（要重启/授权），分发成本高**。
- **方案 B：ScreenCaptureKit 纯音频采集**（现代、免驱动，macOS 13+）
  - Apple 的 ScreenCaptureKit 支持只取系统音频（[Apple 开发者论坛讨论](https://developer.apple.com/forums/thread/718279)）。需要原生代码：Swift/ObjC，或 Rust 绑定 [screencapturekit-rs](https://github.com/doom-fish/screencapturekit-rs)，或 Python [pyobjc](https://github.com/ronaldoussoren/pyobjc/issues/647)。
  - 注意：需要屏幕录制权限；macOS 15 (Sequoia) 上曾有采集回调异常的问题（[pyobjc #647](https://github.com/ronaldoussoren/pyobjc/issues/647)）。
- **Electron 的坑**：Electron 官方 `desktopCapturer` 在 **macOS 上不支持音频采集**（长期限制，官方 [PR #17814 文档说明](https://github.com/electron/electron/pull/17814/files)、[issue #47490 讨论引入 ScreenCaptureKit](https://github.com/electron/electron/issues/47490)）。Electron 在 macOS 上要做系统音频，只能上 native addon（如 [electron-audio-loopback](https://github.com/alectrocute/electron-audio-loopback)，它 macOS 端即用 ScreenCaptureKit）或 BlackHole。

**小结**：Windows 上"谁能碰原生谁就行"，Tauri(Rust)/Electron(native addon)/MAUI(NAudio) 都有现成路径；macOS 上所有框架殊途同归 —— BlackHole（简单通用）或 ScreenCaptureKit（免驱动但要原生 + 权限）。**在 Tauri 架构里，这两条路都可在 Rust 层统一实现，且已有真实项目（taurscribe / voicebox）验证。**

## 2. 调用 ASR 的路径（本地 + 云端）

### 2.1 本地 ASR：faster-whisper（Python/CTranslate2）vs sherpa-onnx（C++）

| 框架 | faster-whisper | sherpa-onnx |
|---|---|---|
| 语言/绑定 | Python（CTranslate2 后端）；无官方 Node/Flutter 绑定 | C 库 + 官方 Python / **Rust** / Node-Addon / **Flutter** / C# / Go / Swift 绑定（见 [sherpa-onnx README](https://github.com/k2-fsa/sherpa-onnx/blob/master/README.md)） |
| 流式 | 社区流式方案（[RealtimeFasterWhisper](https://github.com/fless-lab/RealtimeFasterWhisper) 等） | 官方支持流式（WebSocket / 非流式文件与麦克风示例均有） |
| 生态示例 | 丰富（本地实时转写教程多） | 官方示例最全，含**桌面框架 Tauri / Flutter 官方示例** |

### 2.2 各框架对接本地 ASR

- **Tauri 2.x（最优）**—— 有官方支持的两种形态：
  1. **Rust 直接调 sherpa-onnx（最干净）**：sherpa-onnx 提供 Rust API，且官方仓库 **`tauri-examples/`** 直接内置 [非流式文件识别](https://github.com/k2-fsa/sherpa-onnx/tree/master/tauri-examples/non-streaming-speech-recognition-from-file) 与 [非流式麦克风识别](https://github.com/k2-fsa/sherpa-onnx/tree/master/tauri-examples/non-streaming-speech-recognition-from-microphone) 两个完整 Tauri 模板（文档页：[Tauri Desktop Apps](https://k2-fsa.github.io/sherpa/onnx/tauri/) 已核实存在）。零 Python 依赖、离线、打包干净。
  2. **Python sidecar 跑 faster-whisper**：Tauri 官方文档 [Embedding External Binaries (sidecar)](https://v2.tauri.app/develop/sidecar/) 明确把 "Python CLI applications or API servers bundled using pyinstaller" 列为典型用途；二进制按 `-$TARGET_TRIPLE` 后缀打包（如 `aarch64-apple-darwin`、`x86_64-pc-windows-msvc`）。社区完整示例：[example-tauri-v2-python-server-sidecar](https://github.com/dieharders/example-tauri-v2-python-server-sidecar)。通信走 stdio / localhost HTTP / WebSocket。
- **Electron**：主进程是 Node —— 本地 ASR 建议 **sherpa-onnx 官方 Node-Addon**（[Javascript API 文档](https://k2-fsa.github.io/sherpa/onnx/javascript-api.html)）；faster-whisper 没有官方 Node 绑定，只能 Python sidecar（child_process 拉起 pyinstaller 二进制）或 FFI（node-ffi-napi 调 C API）。**云端 SDK 走 Node 现成包，最顺。**
- **Flutter Desktop**：sherpa-onnx **官方支持 Flutter**（[官方 Flutter 文档](https://k2-fsa.github.io/sherpa/onnx/flutter/)），用 `dart:ffi` 调 C API；faster-whisper 需 Python sidecar。
- **Qt/C++**：直接链接 sherpa-onnx C 库最自然；faster-whisper 用 QProcess 拉起 Python；云端用 QtNetwork/HTTPS。
- **.NET MAUI**：sherpa-onnx 有官方 C# API；云端有 .NET SDK；但 macOS 音频侧弱拖后腿。
- **原生双套**：macOS 用 sherpa-onnx Swift API，Windows 用 C++/C#，各写一遍。

### 2.3 云端 ASR

- 各厂商（Azure Speech、火山引擎、OpenAI Whisper API 等）都有 **Node / Python / C# SDK**，或纯 HTTPS。
- Tauri 里云端 ASR 最直接：Rust `reqwest` 或前端 `fetch`（注意 CORS/能力配置）。**与本地 ASR 完全兼容**——把 ASR 抽象成一个接口，本地/云端可切换。

## 3. UI 表现力：滚动气泡、彩色主题、动画、字体

| 技术栈 | 滚动气泡 | 彩色主题 | 动画 | 字体 | 开发效率 |
|---|---|---|---|---|---|
| **Web（Tauri/Electron 前端）** | ✅✅ 虚拟列表（react-window / virtua）、滚动容器生态最全 | ✅✅ CSS 变量 + dark mode，几行切主题 | ✅✅ CSS/WAAPI/GSAP/Canvas 动画 | ✅✅ webfont + 系统字体栈，text 换行/双向文本支持最好 | ✅✅ 最高（React/Vue 组件库现成） |
| **Flutter** | ✅ ListView/AnimatedList 流畅 | ✅ ThemeData/ColorScheme 内置 | ✅✅ 自绘引擎，ImplicitlyAnimated 细腻 | ✅ 自定义字体/TextStyle 好 | ✅ 高，但聊天气泡要自写组件 |
| **Qt QML** | ✅ ListView + 场景图 GPU 渲染 | ✅ 自定义 Style 系统 | ✅ 声明式动画强 | ✅ 字体控制好 | ⚠️ 中（QML 学习曲线陡，气泡组件少） |
| **Qt Widgets** | ⚠️ 传统，要手写动画 | ⚠️ QSS 主题有限 | ⚠️ QPropertyAnimation 较繁琐 | ✅ 好 | ⚠️ 中 |
| **.NET MAUI** | ⚠️ 桌面端弱 | ⚠️ 主题中等 | ⚠️ 弱 | ⚠️ 中 | ⚠️ 中低 |
| **原生双套** | 各写一遍 | 各写一遍 | 各写一遍 | 各写一遍 | ❌ 低 |

**结论**：对"滚动气泡 + 彩色主题 + 动画 + 字体控制"这一套现代聊天 UI，**Web 技术栈（Tauri/Electron 前端）和 Flutter 并列最强**，Qt 需用 QML 才能接近，Widgets 明显吃力。注意 Electron 渲染层是完整 Chromium（CSS/API 支持 100%），Tauri 是系统 WebView（macOS WKWebView / Windows WebView2，兼容性约 95%+，个别 CSS/API 有差异，需测试）。

## 5. 维护成本与生态（Tauri 2.x vs Electron 为主）

### Tauri 2.x 现状（2025）
- **版本成熟度**：Tauri 2.0 于 2024 年 10 月正式发布，已进入 2.x 稳定迭代，插件体系（`tauri-plugin-*`）官方化：**updater / autostart / single-instance / shell / window-state / clipboard / notifications** 等一应俱全，正合"托盘常驻 + 开机自启 + 单实例 + 自动更新"需求。
- **系统托盘**：官方 `tray-icon` crate 与 `tauri.conf.json` 配置支持 macOS/Win 菜单栏/托盘图标（参考 [macOS Menu Bar App with Tauri v2](https://dev.to/hiyoyok/complete-guide-to-building-a-macos-menu-bar-app-with-tauri-v2-aji)）。
- **音频相关 Rust 依赖**：`cpal`（跨平台采集/播放）、`wasapi`（Windows loopback）、`screencapturekit-rs`（macOS 系统音频）、社区 `tauri-plugin-audio-recorder`。**尚无官方音频采集插件**，音频层需自己用 Rust 写（但已有 taurscribe / voicebox 等开源项目可参考）。
- **学习/维护成本**：需要 Rust（若走 Rust 端音频 + sherpa 集成）；Rust 依赖编译较慢；macOS 用系统 WebView，跨端渲染一致性受系统版本影响。但长期看：体积小、内存低、升级维护面小。

### Electron 现状（2025）
- 十几年历史，生态**最大**：Node 生态现成（音频库、ASR SDK、托盘、自动更新全部成熟），文档与问题库最全，团队若熟 JS 上手最快。
- 痛点：体积/内存（Chromium+Node 全打包）；macOS 系统音频需 native addon（见 §1.2）；WebView 就是 Chromium，包内更新 Chromium 有安全维护负担。

### 其它
- **Flutter Desktop**：官方稳定，但桌面端插件质量参差，系统音频 loopback 与自动更新生态弱（见 §1.2、§4）。
- **Qt**：老牌企业级（商业授权 + LGPL/AGPL 双轨），文档顶级；但现代动画 UI 必须上 QML，聊天类 UI 复用度低，自动更新要自己搭。
- **.NET MAUI**：桌面端支持度明显弱于预期，macOS 音频基本空白，不推荐用于本场景。

## 6. 结论与建议

### 主力推荐：**Tauri 2.x（Rust 后端 + Web 前端）**

理由（对照本场景四项硬需求）：
1. **持续音频采集**：Windows 在 Rust 层直接调 WASAPI loopback（官方标准 API，`wasapi`/`windows` crate）；macOS 两条路都可在 Rust 层统一实现（BlackHole + cpal，或 ScreenCaptureKit 纯音频 + `screencapturekit-rs`）；麦克风用 cpal 或 Web `getUserMedia`。**已有同场景开源项目（taurscribe、voicebox）验证可行。**
2. **本地 ASR**：**sherpa-onnx 官方提供 Rust API 且官方 Tauri 模板现成**（非流式文件/麦克风识别可直接改），零 Python、离线、包内嵌模型；faster-whisper 用官方支持的 Python sidecar（pyinstaller）方案，或双轨并存。
3. **UI**：Web 前端拿满滚动气泡 / 彩色主题 / CSS 动画 / 字体控制的全生态红利，开发效率最高。
4. **托盘常驻 + 打包分发**：官方 tray-icon + autostart + single-instance + updater；安装包最小、Apple Silicon 原生、签名/公证文档齐全。

### 备选一：**Electron（Node + Web）** —— 当团队熟 Node、不想碰 Rust 时

- UI 同 Web 生态（且 Chromium 渲染最一致）；麦克风、托盘、自动更新全部成熟。
- 代价：体积 100MB+；macOS 系统音频要走 native addon（[electron-audio-loopback](https://github.com/alectrocute/electron-audio-loopback) 用 ScreenCaptureKit）或 BlackHole；本地 ASR 用 sherpa-onnx Node-Addon（faster-whisper 需 Python sidecar）。

### 备选二：**Flutter Desktop** —— 当你有"以后还要出移动端"的多端诉求

- sherpa-onnx 官方支持 Flutter（dart:ffi），动画表现力强、跨端像素级一致。
- 代价：macOS/Windows 系统音频 loopback 是生态最弱项（基本要自写原生 channel）；自动更新生态弱。

### 明确排除
- **.NET MAUI**：桌面 + 音频双弱，本场景不合适。
- **Qt Widgets**：UI 表现力不达标（要上 QML 才有竞争力），自动更新要自己搭。
- **原生双套**：工作量翻倍，仅在"性能/系统集成极致 + 无双端人力顾虑"时才考虑。

## 7. 推荐架构落地细节（"音频采集 + 本地 ASR"具体怎么接）

```
┌─────────────────────────────────────────────────────────────┐
│  Web 前端（React/Vue）                                         │
│  · 滚动气泡列表（虚拟滚动 + CSS 主题变量 + 动画）                  │
│  · 监听 Tauri 事件流：增量字幕 / 说话人 / 状态                     │
└──────────────────────────┬──────────────────────────────────┘
                           │  Tauri Event（emit / listen）
┌──────────────────────────┴──────────────────────────────────┐
│  Rust 后端（Tauri core）                                       │
│  · 音频采集线程：                                              │
│      Windows → WASAPI loopback（wasapi/windows crate）        │
│      macOS   → BlackHole 设备（cpal 读） 或 ScreenCaptureKit    │
│                 （screencapturekit-rs，需屏幕录制权限）           │
│  · 麦克风   → cpal（或 Web getUserMedia）                       │
│  · VAD + 分块 → 送入 ASR                                       │
│  · tray-icon 托盘 + tauri-plugin-autostart 开机自启             │
│    + single-instance + tauri-plugin-updater 自动更新           │
└──────┬──────────────────────────────────┬───────────────────┘
       │ 首选（本地离线，零 Python）         │ 备选（更强模型）
       ▼                                   ▼
┌───────────────┐                 ┌───────────────────────────┐
│ sherpa-onnx    │                 │ faster-whisper（Python）    │
│ Rust crate 直调│                 │ = Python sidecar           │
│ （官方 Tauri    │                 │   · pyinstaller 打包成二进制 │
│   模板照抄）     │                 │   · externalBin 按          │
│ · 流式/非流式    │                 │     -$TARGET_TRIPLE 后缀分发 │
│ · 模型随包/首启  │                 │   · Rust 经 stdio/HTTP/     │
│   下载          │                 │     WebSocket 通信          │
└───────────────┘                 └───────────────────────────┘
```

**关键决策点：**
1. **首选 sherpa-onnx（Rust 直调）做默认本地 ASR** —— 官方 Tauri 模板已就绪、离线、无 Python 运行时依赖、打包最干净；中文/多语模型（如 SenseVoice / Whisper 系列 onnx 模型）均可用。
2. **faster-whisper（Python sidecar）作为可选增强** —— 当你需要特定更强模型或熟悉 Python 生态时启用；Tauri 官方把 "pyinstaller 打包的 Python API 服务" 列为 sidecar 典型用例，社区有完整模板（[example-tauri-v2-python-server-sidecar](https://github.com/dieharders/example-tauri-v2-python-server-sidecar)）。
3. **云端 ASR 作为可切换选项** —— Rust `reqwest` 或前端 fetch 调云端 SDK，与本地走同一抽象接口（`fn transcribe(chunk) -> text`）。
4. **系统音频 loopback 是主要工作量**，集中在 Rust 层一次实现、两平台复用同一接口；macOS 建议**先走 BlackHole 方案快速验证**，再评估 ScreenCaptureKit 免驱动方案的体验（需权限弹窗）。
5. **增量字幕体验**：VAD（sherpa 内置 VAD）+ 分窗 whisper 推理 → Rust `app.emit("transcript", ...)` → 前端滚动气泡增量渲染，配虚拟滚动保证长会议不卡。
